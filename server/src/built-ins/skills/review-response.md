# Review Response

**Version:** 1.0

Review rounds are binding. A gate return is not a suggestion to consider — it is a contract the next submission must satisfy.

## How rounds work

When a gate returns feedback, every point in that feedback becomes a binding constraint for the next submission. The round is not closed until every point is addressed. A new submission that fixes the newest complaint while regressing an older fix has not addressed the round — it has traded one failure for another.

**Every round reproduced in your instruction stays binding.** Earlier rounds do not expire when a new one is added. The instruction will carry all rounds verbatim; read all of them before making any change.

## What a response must contain

1. **Address every point.** For each item in the gate return, state what you changed and where. If a point is already satisfied, explain why — do not silently skip it.
2. **Do not defer.** "Will fix in a follow-up" is not a response to a round. If a point cannot be addressed in this session, say so explicitly and stop; do not ship a partial response and mark the round closed.
3. **Do not reopen closed points.** If a prior round accepted a change, do not undo it.

## Sentinel

Review rounds are binding; a gate return must be answered in the round, not deferred.
